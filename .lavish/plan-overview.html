Nine passes, one canvas

The plan works like a painter: Pass 1 puts the entire product on screen in rough strokes — every UI section, every API endpoint, a fake pipeline you can trigger — and each later pass swaps exactly one layer from fake→real or rough→detailed. If the hackathon clock dies after any pass, you still demo a complete whole, never a perfect hand on an empty canvas.

Full detail lives in PLAN.md; source specs in hackathon_handoff/. This page is the map, not the territory.

LAWS Three honesty rules, enforced every pass

These are product features, not engineering hygiene — each has its own test in every gate.

Stale, never blank

A failed probe keeps the last good score, dimmed, with a "stale · timestamp" chip. The page never shows a hole.

Disagree, never average

Conflicting evidence shows both values with a ⚠ banner and is excluded from the score. No silent midpoints.

No-data, never faked

Unmeasurable signatures render hatched with a tooltip naming exactly what's missing. Honesty is the pitch.

LLMs gather evidence; scores are computed — never generated. · Commit after every green gate. · hackathon_handoff/HANDOVER.md governs on any conflict.
